# AI Networking Benchmark Lab (Junior C++ / Linux Project)

[![CI](https://github.com/mohamedtah22/embedded-systems-runtime/actions/workflows/ai-networking-junior.yml/badge.svg)](https://github.com/mohamedtah22/embedded-systems-runtime/actions/workflows/ai-networking-junior.yml)

An **entry-level** hands-on networking and performance project that connects C++17/Linux TCP packet handling to the basic idea of distributed AI communication. It consists of a real TCP data-plane benchmark and a **separate educational mathematical** collective-communication model. No special hardware required.

## What I built

- **TCP sender/receiver** using POSIX sockets in C++17, length-bounded binary framing, CRC32, ordered sequence IDs, and `send`/`recv` loops that handle partial I/O.
- **Multiclient server** handles multiple independent client connections using threads; a negative test verifies that corrupted replies are detected.
- **Performance measurement** records verified round trips, p50/p95/p99 latency (one outstanding frame), and useful payload throughput for different message sizes.
- **Simple AI collective cost model** estimates *idealized* ring vs. tree AllReduce time for different rank counts, tensor sizes and link latencies. **This is a formula comparison, not a working AllReduce network.**
- **Testing and CI** through pytest, CTest, CMake strict compiler flags, and GitHub Actions, with machine-readable JSON/JUnit outputs.

## Why AI networking?

Distributed AI training exchanges tensors between workers. The time spent communicating depends on message size, network bandwidth, and latency. This lab isolates the **junior-level skills** of implementing and debugging sockets, benchmarking real traffic, validating data integrity, and reasoning about the trade-offs between communication patterns.

## Quick start (Linux)

Requires Linux, CMake >= 3.16, g++ (C++17), Python >=3.10 and pytest.

```bash
cd projects/ai-networking-benchmark-lab
python3 -m pip install -r requirements-dev.txt
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
python3 -m pytest -v tests
python3 scripts/bench_matrix.py --binary ./build/tensor_transport --iters 100
./build/collective_model --ranks 4 --tensor-mib 64 --gbps 100 --latency-us 5
```

Example output (shape; measurements depend on the machine):

```json
{"transport":"tcp","payload_bytes":4096,"rtt_p50_us":75.3,"verified":true}
```

Run a custom TCP benchmark in two terminals:

```bash
./build/tensor_transport server --port 9001 --max-clients 1
./build/tensor_transport bench --port 9001 --bytes 4096 --iters 200 --warmup 10
```

`reports/benchmarks.json` is generated by the benchmark runner. `docs/TEST_PLAN.md` describes test coverage and limitations.

## Known limitations

This project is educational. It **does not** implement RDMA, RoCE, InfiniBand, GPU collective kernels, CUDA, NCCL, or real distributed AllReduce. The TCP measurements use local loopback, not physical NIC bandwidth. The model omits contention, PCIe transfers, congestion, GPU synchronization and overlap. The lab is best viewed as a **junior systems/networking exercise**, not an experienced software architect portfolio.
